1. Introduction

Open-Source Software Engineering is the process of developing software whose source code is publicly available for users and developers to view, modify, and contribute to.

GitHub is a platform that supports open-source development by allowing multiple developers to collaborate, share code, fix errors, and improve software documentation.

2. Problem Analysis

A group of developers is developing an open-source Library Management System hosted on GitHub.

However, the project lacks proper documentation explaining how users can issue and return books.

This creates difficulties for users in understanding the system's functionality.

To solve this problem, a student can contribute by creating or modifying the documentation and submitting the changes to the original GitHub repository.

3. Proposed Solution

The student can contribute to the project by following these steps:

Step 1: Fork the Repository

- Open the original Library Management System repository on GitHub.
- Click the Fork option.
- Select the student's GitHub account.
- Click Create Fork.
- A copy of the original repository will be created in the student's account.

Step 2: Create or Modify Documentation

- Open the forked repository.
- Navigate to the required folder.
- Click Add file → Create new file.
- Create a Markdown file named "USN_Library_Documentation.md".
- Add documentation explaining:
  - Introduction to the Library Management System.
  - Steps to issue books.
  - Steps to return books.
  - Important instructions for users.
- Save the file.

Step 3: Commit Changes

- Click Commit changes.
- Enter a suitable commit message, such as "Added Library Management Documentation".
- Commit the changes to the main branch of the student's forked repository.

Step 4: Submit a Pull Request

- Open the student's forked repository.
- Click Contribute → Open pull request.
- Verify the original repository and student's repository.
- Enter a suitable title and description.
- Click Create pull request.

Step 5: Review and Merge

- The original project owner opens the submitted Pull Request.
- Checks the documentation under Files changed.
- Verifies the contribution.
- Clicks Merge pull request to accept the changes.

The updated documentation will now become part of the original project.

5. Benefits and Challenges

Benefits:

1. Collaboration: Multiple developers can work together on the same project.
2. Knowledge Sharing: Developers can learn from other contributors.
3. Improved Documentation: Clear documentation helps users understand the software.
4. Software Quality: Reviewing contributions helps improve the project.

Challenges:

1. Merge Conflicts: Changes made by different contributors may conflict.
2. Review Process: Contributions must be checked before they are accepted.
3. Documentation Accuracy: The information must correctly describe the system's functionality.

6. Conclusion

Open-Source Software Engineering encourages collaboration and knowledge sharing among developers. Using GitHub, students can contribute to existing projects through forking, creating or modifying files, committing changes, and submitting Pull Requests.

In this case study, the student improves the Library Management System by adding proper documentation for issuing and returning books. This makes the project easier to understand and improves its usability.
